# 数据结构

本交付包按《专业知识图谱建设标准》第六章组织，路径均相对于包的根目录：

```text
课程图谱/<课程名称>/知识图谱.json   每门课的课程图谱（§6.1）
专业知识图谱.json                   专业、课程族、课程与全局知识点，及课程间、跨课程知识点间的关系（§6.2）
课程关系汇总表.json                 课程对的关系数量与强度，培养方案对比
课程知识点对齐表.json               全局知识点及其在各课程中的对应知识点（§4.3）
说明/                               本说明与数据层说明、建设方案说明、参考材料
```

所有文件为 UTF-8 编码的 JSON。字段为空时省略。

## 一、课程图谱 `课程图谱/<课程名称>/知识图谱.json`

顶层为 `元信息`、`节点`、`关系`。

### 元信息

| 字段 | 说明 |
|---|---|
| `课程编号`、`课程编号来源` | 课程编号；尚未开课的为 `null`，来源写明首次开课学期 |
| `课程名称` | 课程名称 |
| `理论学时`、`实验学时`、`学分`、`学时来源`、`学时来源差异` | 学时学分及其来源；不同来源不一致时列出 |
| `开课学期`、`开课学期来源` | 按专业给出培养方案中的开课学期，如 `{"人工智能": "第2学年秋季", "数据科学与大数据技术": "第3学年秋季"}`；不在某专业培养方案中的课程没有该专业的键，都不在则为 `{}` |
| `输入模式`、`来源材料` | 依据的大纲与教材（见 [参考材料](参考材料.md)） |
| `知识点数量` | `知识模块`、`知识点` 数量，`要求下限（理论学时 + 0.5 × 实验学时）`，`达标` |
| `关系类型说明` | 四种关系类型的含义 |

### 节点

`类型` 为 `课程`、`章节`、`知识模块`、`知识点` 之一。课程与章节只有 `编号`、`类型`、`名称`。

| 字段 | 说明 |
|---|---|
| `编号` | `课程_<名称>` / `章节_XX` / `知识模块_XX_YY` / `知识点_XX_YY_ZZZ`，按层级嵌套编号 |
| `名称`、`英文名称` | 学科术语 |
| `别名` | 与名称指同一对象的叫法 |
| `检索词` | 上位、下位、组成部分的说法及改名前的名称，供模糊查询 |
| `教学类型` | `理论类` / `实验类` / `实践类` |
| `摘要`、`形式化定义`、`学习目标` | 知识内容；公式为 LaTeX（`$…$`、`$$…$$`） |
| `符号说明` | 形式化定义中公式符号的含义，数组，每项 `符号`（LaTeX）、`含义`、`来源`：`定义`（定义原文给出）、`通用记号`（标准数学记号）、`课程语境`（定义未给出，由摘要或教材原句推断）。由一个模型生成、另一模型逐条复核，复核不成立的不收录；定义中没有公式的节点无此字段 |
| `难度` | 知识模块：`基础` / `核心` |
| `细分类别` | 知识点：`原理性质` / `算法算子`（部分为空） |
| `教材依据` | `书名`、`作者`（部分讲义与综述无）、`章节`、`页码`、`页码类型`（`PDF 页码（已按原文核对）`） |
| `依据` | 对教材内容的概括句，前缀为书名与页码 |
| `教材原句` | `教材依据` 所指页上逐字出现的原文 |
| `大纲依据` | 教学大纲中的对应条目原文（教材中没有该内容时） |
| `依据状态` | 无教材原句时的原因：`not_found_in_course_books`（课程教材未讲）、`quote_not_on_page`、`shared_page_needs_review`（教材中未找到可逐字核对的原句），三者均带 `大纲依据`；`evidence_in_sub_concepts`（知识模块的依据为其下知识点） |
| `原始编号` | 节点的内部编号（`major:<课程>:NNN`、`minor:<课程>:NNN`） |

### 关系

| 字段 | 说明 |
|---|---|
| `编号` | `关系_NNNN`，在本包全部文件中全局流水 |
| `类型` | `包含` / `前置依赖` / `应用` / `关联` |
| `源`、`目标` | 节点编号；前置依赖为“源是学习目标的前提” |
| `子类型` | 关联与应用的细分：`组成部分`、`对比`、`交叉重叠`、`相关`、`实例` |
| `理由`、`依据` | 该关系成立的说明 |
| `依赖强度`、`置信度` | 0–1 |

`包含` 关系构成 课程 → 章节 → 知识模块 → 知识点 的层级，每个节点恰有一个上级。

示例（知识点与一条前置依赖，长文本已截断）：

```json
{
```

## 二、专业知识图谱 `专业知识图谱.json`

顶层为 `说明`、`节点`、`关系`。跨课程关系的 `源`、`目标` 写作 `<课程名称>/<节点编号>`，指向 `课程图谱/<课程名称>/知识图谱.json` 中的节点。

### 节点

| `类型` | 字段 |
|---|---|
| `专业` | `编号`（`专业_人工智能与数据科学`）、`名称` |
| `课程族` | `编号`（`课程族_<名称>`）、`名称`、`成员`（课程名称列表） |
| `课程` | `编号`、`名称`、`课程编号`、`学时`（`理论`、`实验`）、`学分`、`开课学期`（按专业，同课程图谱元信息）、`课程图谱`（该课课程图谱文件的路径） |
| `全局知识点` | `编号`（`全局知识点_NNNN`）、`名称`、`英文名称` |

### 关系

| `类型` | `层级` | 源 → 目标 | 其他字段 |
|---|---|---|---|
| `包含` | — | 专业 → 课程族、专业 → 课程 | — |
| `belongs_to_family` | — | 课程 → 课程族 | — |
| `version_variant_of` | — | 课程 → 课程（同主题的另一版本） | `理由` |
| `前置依赖` / `关联` | `课程` | 课程 → 课程 | `子类型`、`依据` |
| `前置依赖` / `应用` / `关联` | `知识模块` | 知识模块 → 另一课程的知识模块 | `子类型`、`依据`、`核对`（第二个模型的核对意见）、`依赖强度` |
| `前置依赖` / `应用` / `关联` | `知识点` | 知识点 → 另一课程的知识点 | 同上，另有 `上级关系`（`源`、`目标`：所属的知识模块级关系） |
| `前置依赖` | `知识模块` | 知识模块 → 另一课程的知识模块（知识模块级前置依赖） | `理由`、`核对` |
| `对齐` | — | 课程中的知识模块或知识点 → 全局知识点 | — |

## 三、课程关系汇总表 `课程关系汇总表.json`

| 字段 | 说明 |
|---|---|
| `强度定义` | 三种强度的计算方式（见 [建设方案说明](建设方案说明.md) 第七节） |
| `课程对[]` | 每个有关系或对齐的课程对一项 |
| `课程对[].课程A`、`课程B` | 课程名称 |
| `课程对[].知识点级关系数` | 按关系类型计数，含 `模块级前置依赖` |
| `课程对[].对齐知识点数` | 两门课共有的全局知识点数 |
| `课程对[].前置依赖强度`、`前置依赖评级`、`替代兼容强度` | 按方向给出，键为 `<课程>→<课程>`；评级为 `强前置` / `中前置` / `弱关联` / `—` |
| `课程对[].交叉重叠强度`、`同族课程`、`冗余告警` | 冗余告警：非同族课程交叉重叠强度 > 0.25 |
| `课程对[].支撑强度` | 未计算及原因 |
| `培养方案对比.结果[]` | `先修课程`、`后续课程`、`评级`、`强度`、`专业`（无法比较时为 `null`）、`先修课程开课`、`后续课程开课`（如“第2学年秋季”）、`结论`（一致 / 冲突 / 无法比较）；一个方向在两个专业中都可比较时各有一行 |

## 四、课程知识点对齐表 `课程知识点对齐表.json`

| 字段 | 说明 |
|---|---|
| `对齐规则` | 对齐判定规则（§4.3） |
| `对齐[].全局知识点编号`、`名称`、`英文名称` | 全局知识点，与 `专业知识图谱.json` 中的全局知识点节点一致 |
| `对齐[].涉及课程` | 课程名称列表 |
| `对齐[].对齐项[]` | `课程`、`节点编号`（课程图谱中的编号）、`名称`、`依据`、`教材原句` |
| `对齐[].对齐理由` | 判定为同一知识对象的理由 |
